# 博客提供入口，各自打开本地工具页面并写入自己的目标仓库

创作工具第一版优先服务作者本人，同时允许其他人安装并使用；博客提供公开工具入口和使用说明，每位使用者启动自己的工具后，打开自己的本地工具页面，使用自己的CLI/模型凭据，并把文章和图片等成果写入自己选择的目标仓库。选择这种方式，方便未来复用源码，同时无需在公开博客维护共享操作页面、集中持有凭据或替所有人运行任务。

作者于2026-10-26明确澄清“工具页面也是各用各的”；本ADR据此修正此前“共用公开工具操作页面”的理解。博客未连接工具时展示使用说明、已启动时引导进入本地工具的体验保留，探测或导航的具体机制待设计；公开网页直接调用本地任务API不作为既定架构。

这一决定沿用IverBlog当前公开静态博客边界；工具独立项目的边界见本仓库ADR 0002。作者已确认文章预览后明确发布，工具提交本次文章/封面并推送配置的发布分支，沿用目标仓库已有自动部署；目标博客格式支持、发布前检查与失败恢复仍待设计。本文不表示服务或页面已实现，也不授权本次执行Git发布、公开仓库或部署网站。

作者进一步明确，工具成果是当前目标博客内的代码/配置、Markdown与图片变更；文章、后续作品与首页场景都沿用该博客的提交推送和既有Cloudflare部署链路。工具源码独立不意味着作品源码必须另建仓库或独立托管，不将此前Agent提出的跨仓库方案作为需求。
