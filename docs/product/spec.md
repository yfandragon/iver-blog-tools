# 本地创作工具：首版规格草案

Status: runnable-slice

更新日期：2026-10-28（Asia/Shanghai）

阶段：首个可运行切片已实现；Markdown/HTML 双格式导入、资源检查、隔离展示和全文搜索已扩展到本地验收范围。工具流程可补齐元数据、校验独立封面、写入目标仓库预览、展示完整文件清单，并在显式确认后提交推送。Antigravity 保持禁用，直到确认官方许可和账号计划。实现证据见[项目上下文](../PROJECT_CONTEXT.md)和[开发记录](../development-log.md)。

## 目标

提供可扩展的本地创作与发布工具，按文章、作品和首页场景区分功能。首版先完成文章流程：作者在外部编辑器完成Markdown后，通过自己的本地工具页面生成封面、预览，并在明确确认后提交文章与封面至自己的目标仓库。首个接入对象为IverBlog，同时允许其他人以同样方式连接自己的仓库。

## 已确认的项目与运行边界

- 工具自身的代码独立项目维护；它操作的目标是使用者选择的博客项目，IverBlog作为第一个目标仓库。独立工具项目不意味着每个作品还要另建仓库或单独托管。
- 每位使用者启动自己的本地页面和执行服务，使用自己的CLI登录/模型与目标仓库。
- 博客提供公开工具入口及使用说明。未启动时显示说明，启动后引导进入本地工具；具体探测、导航与浏览器打开方式待设计。
- 首版兼容IverBlog当前的Astro + Markdown内容约定，其他人连接相同约定的自己的仓库；不要求首版自动适配任意博客框架。
- 未来可能开放工具源码；当前没有执行仓库公开或网站上线。

架构依据：[ADR 0001](../adr/0001-local-execution-per-user.md)、[ADR 0002](../adr/0002-independent-tool-project.md)。

## 已确认的仓库与部署触发边界

| 操作 | 影响 |
| --- | --- |
| 修改、提交或push工具源码仓库 | 更新工具自身，不触发IverBlog的Cloudflare部署 |
| 工具生成图片、修改目标博客本地文件或运行预览 | 仅本地准备，不自动提交或push，不触发公开部署 |
| 作者确认发布后，提交并push目标博客的配置发布分支 | 由该博客已有Cloudflare配置触发构建部署 |

工具版本发布与博客内容发布分别管理；不将工具仓库接入IverBlog的部署触发源，也不因工具更新自动push博客。博客已有自动部署配置是这条链路的前提，本文记录架构约定，不冒称本轮重新核验了平台状态。

## 已确认的功能分类与交付顺序

| 功能 | 目标 | 交付顺序与边界 |
| --- | --- | --- |
| 文章 | 导入外部完成的Markdown、AI封面、真实博客预览、确认后提交推送 | 首版完整实现 |
| 作品 | 把作品材料及需要的博客页面代码接入当前目标博客，真实预览后确认提交推送 | 后续功能；默认沿用目标博客仓库及其部署链路，具体材料按实际作品确定 |
| 首页场景 | 沿用现有背景提示词生成候选，按场景规则适配和评审后再接入/发布 | 文章流程完成后扩展；不与文章封面混用模板或关联方式 |

工具结构从开始就按功能类型组织，不能把所有处理写成文章专用的唯一流程。后续功能尚未实现时不提供假成功操作或在公开博客创建空作品区；具体入口呈现方式由实现设计确定。

首页场景的默认模板来源是[场景接入规则](../../../iverBlog/.scratch/blog-evolution/background-scenes.md)和[背景生成记录](../../../iverBlog/.scratch/blog-evolution/background-generation.md)，保留现有原版与历史。使用者可修改副本，修改不覆盖原版；不同功能各用自己的模板与预览/发布步骤。首页场景后续需同时检查桌面/手机裁切、首屏到文章区连续性与文字可读性；生成候选、接入本地、加入轮换和公开发布仍是不同阶段。

统一成果是当前目标博客仓库中与本任务相关的文件变更：Markdown、图片、元数据，以及该功能所需的页面代码或配置。文章、作品、首页场景分别处理材料和关联，但统一使用“修改目标博客 → 真实本地预览 → 作者确认 → 提交并push博客发布分支 → 现有Cloudflare自动构建部署”的主干。此前Agent提出的“另设作品仓库、单独作品站点、再回写博客链接”并非作者需求，不作为默认作品架构。

工具不需要为每个作品自动新建Cloudflare项目；作品内容先按当前Astro博客的构建与路由接入，所需作品页面/内容集合基础在后续功能实施时补齐。推送成功、Cloudflare构建部署成功和公开页面验证分别记录，不以一个状态替代全部结果。

## 已确认的文章流程

1. 导入在外部写好的Markdown、HTML，或包含笔记与资源的目录/ZIP；多个入口时由作者选择。原始包快照保留在本机任务目录。
2. 选择一个已安装且当前获准使用的CLI，再选择其运行时可用并经过任务能力验证的模型/路径；载入文章封面功能提示词，允许本次临时调整。Codex为已验证可用的路径；Antigravity须通过账号计划/调用许可门控。
3. AI阅读文章以构思和生成封面，不改写正文、不自动往正文插图。
4. 工具取得真实图片，处理网页资源并在文章元数据中建立明确封面关联。
5. 启动目标博客的真实本地预览，作者查看首页文章卡片的封面/标题/裁切，并打开文章页检查正文、代码和已有图片。具体嵌入或新标签打开方式及运行隔离由实现设计确定。
6. 作者明确确认发布后，工具只提交本次文章、所选封面及必要关联内容，并推送到配置的发布分支；目标仓库已有自动部署时沿用。

Markdown 正文保持原稿内容，仅派生副本中的本地资源地址改写到 `public/note-assets/<id>/`。HTML 原稿作为 `src/content/articles/<id>.html` 原样保存，资源按原目录层级写入 `public/note-assets/<id>/`；封面仍单独生成、解码校验并明确关联，不使用 HTML `og:image` 代替。

## 已确认的文章信息与速查范围

- 标题、摘要、发布日期已有值时沿用，并在工具内提供可编辑字段。
- 缺失标题时从Markdown正文标题或文件名提取建议值；缺失摘要时由所选CLI拟草稿，作者可以修改。
- 日期缺失时默认当天；提供日期选择器并允许手动修改，发布使用作者最终选择的日期，不把日期固定为导入或生图当天。发布触发仍沿用已确认的“预览后点击确认上传”。
- 新工具不自动新增或填写`quickReference`，不要求生成“常用配置速查”等首页卡片折叠区域，也不将该字段设为发布必填项。
- 正文里的代码和配置保留。作者倾向未来从现有博客卡片移除折叠速查，该站点优化另行处理；本次工具讨论不删除旧文章字段或改现有卡片组件。


### Markdown / HTML 笔记导入实现约定

- Markdown 沿用现有文章集合和 URL。HTML 条目使用仅含元数据的 `.md` 文件，字段 `contentFormat: 'html'`、`htmlSource` 和可选的 `htmlBasePath` 指向原稿及资源基准目录。首页卡片仍由同一内容集合生成。
- HTML 文章页保留博客导航、元数据和返回入口，以 `srcdoc` sandbox iframe 呈现；sandbox 只开放脚本与弹窗，不开放 `allow-same-origin` 或顶层导航。完整页面路由复用同一原稿，并提供固定返回入口。复制桥接校验来源窗口、opaque origin、实例标识、消息类型、请求 ID 和文本长度。
- HTML/CSS/JavaScript 模块与 Markdown 资源引用使用语法解析器扫描。外部 HTTP(S) 依赖保留并标示；缺失资源、本机绝对路径、动态依赖和活动 HTML/SVG 文档等不可安全解析项显示位置与原因并阻止准备。SVG 仅作为图片使用。
- ZIP 与文件夹输入均校验路径穿越、绝对路径、规范化重名、文件数量和体积；ZIP 流式读取并拒绝符号链接。限制：100 MiB 压缩体积、256 MiB 展开体积、2,000 个文件、单文件 50 MiB。浏览器 File API 不暴露文件夹中 symlink 的元数据，因此选择文件夹时不能声称已完成 symlink 校验；需校验链接时使用 ZIP。
- 预览清单包含元数据、原始 HTML、已引用资源和独立封面，并记录 SHA-256。元数据修改使旧预览失效但保留导入阻塞项；重新准备仅在既有任务文件与快照一致时原位更新。HTML 目标仓库若无明确承载与搜索能力则拒绝写入。
- 构建使用 Pagefind 1.5.2 Node API、中文单一索引和 `._-+` 字符设置。HTML 普通页面记录排除，构建脚本从原稿提取标题、摘要、正文与代码，跳过脚本、样式、隐藏内容和结构化数据，并将自定义记录指向原文章 URL。

## 提示词与CLI接入

- 首版目标支持Codex CLI与Antigravity CLI；OpenCode Go/DS或dsh仍不在本轮范围。Codex已验证一条实际产物链路；Antigravity仅验证了`gemini-3.8-flash-high`委派原生`image-generator`子代理后生成JPEG，未证明其他型号均可生图。父级响应没有直接返回文件，适配器必须等待子代理完成、从会话托管目录取回文件并校验。[官方FAQ](https://www.antigravity.google/docs/faq)称第三方软件/工具访问Antigravity可能违反条款，且消费者计划不支持在第三方应用中包装`agy`；本地工作台的CLI包装必须先核实允许的账号/调用方式，消费者计划不得启用此适配器。
- 不同功能选择对应的功能提示词；本次提示词可临时编辑，不能回写原模板。实现时必须有实际写入边界，不能只提醒模型遵守。
- 文章封面默认使用作者于2026-10-28提供的三段原文，保存为 [`prompts/article-cover/v2.md`](../../prompts/article-cover/v2.md)，保留 v1 历史基线。要求原创16:9自然或生活场景的二维手绘动漫环境画，中央约70%的主体在360px缩略图和中心3:2裁切中仍完整；具体禁用元素、近期封面差异和单张检查要求以原文为准。新导入任务使用 v2，已有任务副本不自动替换。此次只更新提示词，不表示已实现近期封面自动收集或图像构图自动验收。
- 对每个启用的CLI提供其运行时可用模型选择；模型可用性与具体生图能力分开判断，不能把推理模型名称当成图像生成模型或工具的名称。
- CLI返回文字成功、退出0、绘图提示词或Markdown图片链接不足以证明生图成功；需取得可解码图片并验证本地页面能读取。
- 首个切片已实现 Codex 非交互摘要/生图、真实图片回收、解码验证、目标博客写入和 Astro 真实预览。Codex 的模型目录使用 app-server `model/list`，但不据此宣称账户调用权限；只有历史实测过的封面模型开放生图。Antigravity委派路径已有JPEG产物证据，但正式工具保持关闭，直到其调用计划/方式获官方允许。见[实测记录](../testing/cli-image-validation-2026-10-26.md)、[能力记录](../research/model-capability-audit.md)和[开发记录](../development-log.md)。

## 当前切片的实现边界

1. 只创建新文章。同名文章被拒绝覆盖；更新已有文章或替换现有封面留待后续设计。
2. 远程图片引用保留原样并显示外链提示；已解析的本地资源随任务清单写入博客，缺失或无法静态解析的依赖会阻止预览准备。
3. 只接受当前已核对的 IverBlog Astro schema 与目录结构，不支持任意 Astro 仓库或其他博客框架。
4. Codex `app-server` `model/list` 用于读取目录，不代表当前账号对所列模型具备实际调用权限。模型目录和生图能力分别展示；封面仅允许此前已实测过的 `gpt-6.1-sol` 路径。
5. Antigravity 的模型/生图链路虽然曾在独立核验中产出图片，但本地工具不检查或调用 `agy`，直到确认调用方式和账号计划符合官方许可。
6. 任务数据和生成原图使用系统临时目录，应用重启后不恢复任务；工具安装分发、公开博客入口、作品和首页场景功能未实现。
7. 工具显示推送成功只表示目标 Git 远端接受提交，不表示 Cloudflare 构建或公开页面已验证。

这些是首个切片之后的实现边界和后续功能范围，不改变本文已确认的文章流程。
